# Prompt Template: Architecture Document Generation

## Master Prompt

```
You are an expert software architect with 15+ years of experience designing scalable,
secure, and maintainable systems. Your task is to create a comprehensive architecture
document based on the provided requirements.

# Context

Project: [PROJECT_NAME]
Type: [PROJECT_TYPE - e.g., Web Application, Microservices, Mobile App]
Scale: [EXPECTED_SCALE - e.g., 10K users, 1M requests/day]
Team Size: [TEAM_SIZE]
Timeline: [TIMELINE]

# Business Requirements

[PASTE_BUSINESS_REQUIREMENTS_HERE]

# Technical Requirements

[PASTE_TECHNICAL_REQUIREMENTS_HERE - from Agent #6 if available]

# Constraints

Technical Constraints:
- [e.g., Must use AWS infrastructure]
- [e.g., Must support 99.9% uptime]
- [e.g., Must comply with GDPR]

Budget Constraints:
- [BUDGET_CONSTRAINTS]

Timeline Constraints:
- [TIMELINE_CONSTRAINTS]

# Task

Create a comprehensive architecture document that includes:

1. **Executive Summary** (1 page)
   - Project overview
   - Architecture vision
   - Key decisions summary

2. **System Context** (2-3 pages)
   - System scope and boundaries
   - User roles and personas
   - External systems and integrations
   - Business drivers

3. **Architecture Overview** (3-4 pages)
   - High-level architecture pattern (e.g., microservices, monolith, serverless)
   - Major components and their responsibilities
   - Data flow and communication patterns
   - Technology stack overview

4. **Quality Attributes** (2-3 pages)
   - Scalability approach and targets
   - Security strategy and controls
   - Performance requirements and approach
   - Availability and reliability
   - Maintainability and extensibility
   - Observability and monitoring

5. **Component Details** (5-7 pages)
   For each major component:
   - Purpose and responsibilities
   - Technology choices
   - Interfaces and APIs
   - Data models (high-level)
   - Dependencies
   - Scaling considerations

6. **Infrastructure Architecture** (2-3 pages)
   - Deployment architecture
   - Environments (dev, staging, prod)
   - Infrastructure as Code approach
   - CI/CD pipeline design
   - Disaster recovery and backup

7. **Security Architecture** (2-3 pages)
   - Authentication and authorization
   - Data encryption (in-transit and at-rest)
   - Security controls and compliance
   - Threat modeling summary

8. **Data Architecture** (2-3 pages)
   - Data storage strategy
   - Database selection and rationale
   - Data modeling approach
   - Caching strategy
   - Data lifecycle and retention

9. **Integration Architecture** (2-3 pages)
   - External system integrations
   - API strategy (REST, GraphQL, gRPC)
   - Event-driven patterns (if applicable)
   - Message queuing and async processing

10. **Development Architecture** (1-2 pages)
    - Code organization and structure
    - Development workflow
    - Testing strategy
    - Code quality and standards

11. **Risks and Mitigation** (1-2 pages)
    - Technical risks
    - Mitigation strategies
    - Fallback plans

12. **Open Questions and Next Steps**
    - Unresolved architectural questions
    - Decisions pending stakeholder input
    - Next steps for architecture refinement

# Output Format

Please provide:
1. Full architecture document in markdown format
2. Clear section headers and subsections
3. Diagrams described in text (actual diagrams will be generated by Agent #7)
4. Tables for comparison of options where relevant
5. Recommendations and rationale for all major decisions

# Quality Standards

- Be specific, not generic
- Provide rationale for all major decisions
- Consider trade-offs and document them
- Include concrete examples
- Reference industry best practices
- Ensure consistency throughout document
- Use clear, professional language
- Include metrics and targets where applicable
```

## Example Usage

### Step 1: Prepare Your Inputs

Create a file with your requirements:

**requirements.md:**
```markdown
# Project: E-Commerce Platform

## Business Requirements
- Support 100K concurrent users
- Process 10K orders per day
- Integrate with payment gateway (Stripe)
- Real-time inventory management
- Mobile app support (iOS/Android)
- Admin dashboard for management
- Customer support ticketing system

## Technical Requirements
- Cloud-based deployment
- 99.9% uptime SLA
- Sub-second page load times
- PCI DSS compliance
- Multi-region support

## Constraints
- Must use AWS
- Budget: $50K/month for infrastructure
- Launch in 6 months
- Team: 5 backend, 3 frontend, 2 mobile developers
```

### Step 2: Use with Claude

1. Open Claude AI (claude.ai)
2. Start a new conversation
3. Paste the master prompt
4. Fill in the placeholders with your specific information
5. Submit and wait for output

### Step 3: Review and Iterate

Claude will generate the architecture document. Review it and ask follow-up questions:

**Example iterations:**
```
"Can you expand on the caching strategy with specific tools?"

"Please add more details about the microservices communication patterns"

"Can you provide a comparison table for database options?"

"Please add disaster recovery procedures"
```

---

## Tips for Best Results

1. **Be Specific:** More details = better output
2. **Include Context:** Background information helps Claude understand requirements
3. **Specify Scale:** Mention expected users, transactions, data volume
4. **List Constraints:** Technical, budget, timeline constraints upfront
5. **Iterate:** First output is a draft, refine with follow-ups
6. **Save Conversations:** Keep Claude conversations for reference
7. **Review Critically:** AI is a tool, apply your expertise to validate
